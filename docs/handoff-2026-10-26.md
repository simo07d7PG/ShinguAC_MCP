## 4. 진행 중이던 작업 — 다음 세션이 이어서 할 것

### 4.1 Phase 4 리뷰 지적 수정 (실행자 `exec-fix1`에게 위임했던 목록)
세션 종료 시점에 수정이 **완료되지 않았을 수 있다**. 먼저 `git status`로 미커밋 변경을 확인하고, 있으면 `npm run typecheck && npm test`로 상태를 본 뒤 항목별로 검토·커밋한다(없으면 아래를 직접 구현).

**MAJOR**
- M1 **E클래스 "현재 강의" 세션 상태 경합**: `POST /eclass/clas/home`이 세션에 현재 강의를 저장하므로 병렬 도구 호출 시 과목 귀속이 틀어질 수 있음. 수정안: `SessionManager.generation` 공개 + `CategoryService`에 async mutex, `ensureLecture(lectureSeq)`가 `{lectureSeq, generation}`을 기억해 재로그인(세대 변경)·강의 변경 시 재진입. 모든 `/eclass/clas/...` 읽기 직전에 호출. (`category-service.ts:117-125,164-171,193-194,224-225`, `session-manager.ts:38-42`)
- M2 **스냅샷 의미 보존**(계획 1.2 "필터 전 전체 저장"): courses `includeContacts=false` 수집이 연락처 포함 스냅샷을 덮어씀 → 기존 연락처 병합; notices `includeEclass=false`가 eclass 공지를 지움 → 보존 + live/snapshot 동일 필터; assignments `unknown`이 기존 known 상태를 덮음 → reportSeq 기준 유지.
- M3 **빈 배열 오판**: `parseEclassHome`·`parseEclassBoardList`가 컨테이너 부재에도 `[]` 반환 → 빈 상태 문구("E클래스 정보가 없습니다"/"데이터가 없습니다")가 없으면 `ParseError`.

**MINOR**(코드 리뷰 m1~m11 + 보안 M1/M2): 스냅샷 쓰기 실패 시 live 결과 반환; 손상 스냅샷은 "없음" 취급 + 스키마 검증; 상세 대상 선정과 반환 필터 기준 통일(`effectiveDeadline` 23:59:59); `AuthUnsupportedError`도 회로 차단; 자격증명 POST 재시도 0(`RequestQueue.enqueue(fn,{retries})`); 입력 오류 전용 `InputError`; `parseNoticeId` 엄격 검증(`bbsSeq` 숫자만) + `encodeURIComponent`; 스냅샷 디렉터리 0o700/파일 0o600; `grades.ts num()` 비숫자 → null; `DAY_MS`·날짜 포맷·`stripComments` 중복 통합; `get-timetable`의 `new Date()` 주입 가능하게.

**보안 리뷰 나머지(LOW, 선택)**: 307/308에서 자격증명 본문 재전송 제한(login 호스트만), 공개 CMS 요청은 별도 빈 쿠키 jar 사용, 보고가 잘려 L3~L5는 미확인(`npm audit --omit=dev` 0건).

### 4.2 재검증과 마무리
1. 수정 후 `npm run typecheck && npm run build && npm test`, `npm run smoke`(실계정), `npm run smoke:stale`.
2. **AC-E1 재측정**: 첫 `get_assignments({due_within_days:7})` 15.5초(기준 15초, 경계). 제출 시작 전 과제 상세 생략(97615d3) 이후 미측정 — `npm run smoke` 첫 줄로 확인. 여전히 >15초면 사용자에게 (a) 기준 완화 (b) 상세 조회 범위 축소 중 결정 요청.
3. Phase 4 재검증: architect · security-reviewer · code-reviewer를 다시 돌려 APPROVE 받기(이전 판정: architect REJECT, code REJECT, security LOW/판정 미수신).
4. `docs/e2e-checklist.md` 갱신(재측정값, 재검증 결과).
5. Phase 5: `.omc/notepads/autopilot/problems.md`에 관찰 3줄 이내, 상태 파일 정리(`/oh-my-claudecode:cancel`). **push는 사용자 요청 시에만**(`COMMIT.md`).

### 4.3 연기된 구성요소
- 플러그인 패키징/배포(딥 인터뷰 Round 0에서 연기): 현재는 `claude mcp add` 또는 `.mcp.json` 수동 등록. 멀티유저 배포를 위해선 `npx github:<owner>/<repo>` 실행(`package.json` `prepare` 빌드) 또는 플러그인 마켓플레이스 패키징이 후속 과제.

## 6. 실행 명령 모음

```sh
npm ci && npm run build          # 빌드
npm test && npm run typecheck    # 169 tests
npm run smoke                    # dist 서버를 stdio로 띄워 7개 도구 실계정 호출 (.env 필요)
npm run smoke:service            # CategoryService 직접 호출
npm run smoke:stale              # 실패 fetch 주입 → 스냅샷 fallback 확인 (~/.shingu-mcp/config.json 사용)
npm run recon:login              # 로그인 체인 실측
npm run check:pii                # 픽스처에 .env 값·실명 잔존 검사
MASK_STUDENT_NAME=<실명> MASK_PROFESSORS=<이름,...> npm run mask   # raw → 마스킹 픽스처 재생성
```

## 7. 주의

- `.env`, `tests/fixtures/raw/`, `~/.shingu-mcp/`에 실제 학번·비밀번호·성적이 있다. 출력·커밋 금지. 픽스처 재생성 시 실명은 env로만 전달(스크립트에 적지 말 것).
- 커밋 메시지는 `COMMIT.md`: `[Type] 한국어 제목`, **본문에 "claude"라는 단어도 금지**(commit-msg 훅이 거부 — `claude mcp add` 같은 명령어도 안 됨).
- 포털 요청은 반드시 `RequestQueue` 경유. 실계정 스모크는 로그인 1회 + 수십 요청이므로 반복 실행 자제.
- 커밋 시 `git add -A` 금지 — 병렬 실행자의 미완성 파일이 섞인 적이 있음(경로를 명시해 stage).
